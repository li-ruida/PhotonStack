# 单色母片合色与通道表达式

入口：后期调整 → 高级 → 多滤镜合色与表达式。

1. 选择 HOO、SHO、RGB 或 LRGB 作为映射起点，再为变量选择单色线性 FITS 母片。可添加其他变量，最多 16 张；变量区分大小写。
2. 确认各母片已经完成校准并配准到相同的像素网格。选择新文件后需重新确认。此入口不会自动配准、匹配曝光/背景或均衡星点宽度。
3. 编辑 R、G、B 的表达式，选择“合色并另存线性母片”。结果自动进入主画布，原始线性数值保存在 FITS 中，显示预览的拉伸不写回母片。
4. “打开合色配方”恢复所有变量、来源路径和表达式。修改表达式后再另存；“查看合色/有效范围”不会丢失待应用的表达式。新配方解除已打开结果的来源绑定，需再次确认配准。

## 映射和数值定义

| 起点 | R | G | B |
|---|---|---|---|
| HOO | Ha | OIII | OIII |
| SHO | SII | Ha | OIII |
| RGB | R | G | B |
| LRGB | L×R/Y | L×G/Y | L×B/Y |

LRGB 中 `Y = 0.2126*R + 0.7152*G + 0.0722*B`，逐像素按 L/Y 缩放三色，保留 RGB 比例。这是明确的线性亮度替换公式，不是 Lab 合色，也不自动估计滤镜响应或通带曝光倍率。用户需让母片强度适合此映射；零分母产生无效像素。保留有符号数值，不自动抬升黑场或截断到 0–1。两条实测通带不能凭此生成独立实测 SII，SHO 必须提供对应信号。

表达式支持十进制/科学计数常数、变量、括号、一元正负号、`+ - * /`，以及 `abs(x)`、`sqrt(x)`、`min(a,b)`、`max(a,b)`、`pow(a,b)`。乘除优先于加减，同优先级从左到右；乘方使用 `pow`，不是 `^`。无脚本执行、文件访问、循环或可修改全局变量。每个表达式最多 4096 字符、256 条计算指令、32 层嵌套。

每个输出像素的三色都必须有效；被引用母片的 NaN/Inf、除零、负数开方及 Float32 溢出会使整像素无效。不会用 `min/max` 隐藏缺失输入。没有被表达式引用的变量不参与有效性判断。所有像素无效时拒绝发布结果。`RGB.fits` 为线性 Float32 RGBA，透明度 0 代表缺失；`validity.fits` 是相应的 0/1 有效图，**不是**曝光权重或几何覆盖率。

输入必须为单色 FITS，拒绝 RGB、带 `BAYERPAT` 的 CFA 原片和已声明的非线性显示编码。所有母片尺寸必须相同。有解算的母片之间检查 9×9 网格坐标，偏差超过 0.05 像素拒绝合色；此检查仅验证所提供坐标的一致性，不代替星表精度验证或实际恒星配准。全部母片都有一致的受支持 WCS 时，保留 TAN/SIP 坐标；部分缺失时不把某一张的坐标冒充为共同坐标。错误或不受支持的 WCS 不静默丢弃。

## 命令行与重跑

```sh
photonstack channel-compose --aligned \
  --input Ha=/data/Ha.fits --input OIII=/data/OIII.fits \
  --red 'Ha' --green '0.25*Ha+0.75*OIII' --blue 'OIII' \
  --output-dir /data/hoo-mixed

photonstack channel-inspect --recipe /data/hoo-mixed/recipe.txt
photonstack channel-replay --recipe /data/hoo-mixed/recipe.txt \
  --green '0.5*Ha+0.5*OIII' --output-dir /data/hoo-remixed
```

`--aligned` 是用户对预先配准的明确确认，不是执行配准。新输出目录不能已存在，App 的原子保存也执行相同规则。配方保存完整输入路径、来源 SHA-256、三条表达式和输出摘要；查看/重开校验来源和输出，重跑校验来源。源文件变化不会默默重算。文件未改时重跑的科学输出可逐字节复验。

当前执行为 CPU 多线程，默认最多 8 个工作分段，也可用 `--workers 1..64` 指定；不是 GPU 运算。运行报告中的 `workers` 是逻辑工作分段数，不是采样得到的同时活跃线程数。输入逐张读入并保留单色平面，表达式编译一次，逐像素使用固定大小栈，无逐像素字符串解析或堆内存分配。真实数据、串并行一致性与峰值内存记录见[验收记录](advanced-imaging-validation.zh-CN.md)。
