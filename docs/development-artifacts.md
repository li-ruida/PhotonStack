# 本地开发与成图产物

`apps/`、`engine/`、`packages/`、`tests/` 和 `tools/` 是软件源码与工具。`build/`、`.build/` 是可重建的编译与临时处理目录；需要长期保留的本地成图、项目和记录集中在 `artifacts/`。这些本地产物均忽略版本控制。已安装 App 的程序不依赖编译目录，但保存的项目仍依赖它引用的母片、成片和报告，不能一起删除。

## 源码目录

| 目录 | 职责 |
| --- | --- |
| `apps/` | 桌面 App 与命令行程序入口 |
| `engine/` | 共享 C++ 图像处理引擎及桥接接口 |
| `packages/` | Swift 数据模型、处理服务和界面 |
| `tests/` | 引擎及命令行测试；Swift 测试随各 package 保存 |
| `tools/scripts/` | 构建、运行、打包、安装和验证工具 |
| `script/` | 现有开发启动兼容入口，转发到 `tools/scripts/` |
| `docs/` | 构建、架构、功能和处理说明 |
| `third_party/` | 第三方源码与许可证 |

## 本地结果与历史记录

本地目录入口为 `artifacts/README.md`，列出实际保留的项目与结果。历史 `CURRENT.json` 中的安装版本、阶段结论属于当时记录，不代表当前安装版本；应核对 App 的构建信息。

| 目录 | 用途 |
| --- | --- |
| `build/`、`.build/` | C++/Swift 编译缓存、打包暂存、虚拟环境、正在进行的实验中间文件 |
| `artifacts/<target>/current/` | 当前科学母片和显示导出 |
| `artifacts/<target>/reference/` | 用户参考与保留的对齐参考 |
| `artifacts/<target>/projects/` | 保存的项目及其必要图像依赖 |
| `artifacts/<target>/reports/` | 可直接阅读的当前报告 |
| `artifacts/<target>/archive/` | 历史配方、指标、脚本和对照图的压缩归档 |
| `artifacts/<target>/maintenance/` | 清理清单、路径迁移、哈希校验及删除记录 |
| `artifacts/app-backups/` | 固定安装 App 的回退包，与可清理的编译目录分开 |
| `artifacts/archive/` | 已完成独立实验的压缩归档，保留归档前相对路径 |
| `artifacts/maintenance/` | 跨目标清理清单、归档成员校验和保留文件校验 |
| `artifacts/calibrated-validation/` | 保留的独立子堆栈与验证输入；不作为普通缓存删除 |

`artifacts/<target>/CURRENT.json` 标识当前结果及校验值；对应 `README.md` 提供本地目录入口。根目录的历史 `PhotonStack-AstroRun-*` 已整理至上述布局，不再保留这些目录或指回旧位置的符号链接。

## 实验结果保留

正在进行的独立实验放在 `build/experiments/<target>/`，不要在仓库根目录建立按日期、版本命名的文件夹。结束后将需要保留的结果迁入 `artifacts/<target>/`，再清理 `build/`。迁移保存的项目时同步修正文件 URL 和处理历史中的路径，并校验所有引用文件存在。

每轮处理结束并完成成图检查后执行一次清理：

- 保留原始素材、用户参考、当前科学母片、最终导出和必要的一组对照。
- 保留体积较小的处理配方、日志、指标、文件身份记录及复现脚本。
- 删除已完成步骤的临时解码/配准帧、断点文件、重复导出和已淘汰方案的过程数组；不为每个参数尝试永久保留一套全分辨率中间图。
- 最近失败任务的排错文件只保留到诊断完成；随后按同样规则清理。
- 清理前记录具体文件清单与大小，确认没有运行中的任务使用它们；不能按“名字像旧版”批量删除整个目录。
- 记录清理结果及当前保留文件。历史成功清单不能被当作临时缓存仍然存在的证明；重跑依赖已清缓存的步骤时，应先按配方重建。

历史归档保留当时的路径与原始记录，不重写旧实验的证据。归档不包含已淘汰的大型成图、累积数组和所有编译输出；复现旧脚本前需要恢复相应布局、重建程序和已清理的中间步骤。原始摄影素材保持在用户的素材目录，不移入源码仓库。

归档前先检查所有保存项目及结果索引的引用，再逐文件校验压缩包。只把不承载现有项目依赖的已完成实验目录整体归档；仍被项目引用的历史目录保持原路径。需要恢复实验时先列出归档内容，将所需目录解压到独立工作目录，避免整包覆盖当前仓库。清理编译缓存后，下一次构建会重新生成 `build/`，无需为每次构建保留一个新目录。

固定安装的 App 仍在 `/Applications/PhotonStack.app`，升级覆盖这个位置。构建产物及回退备份与天文图像实验数据分别管理。
