# 可复用工作流

工作流保存的是当前处理结果的有效操作链，而不是照片本身或整个项目历史。它独立于项目存放，适合处理完一组照片后，将同样的堆栈和后期步骤应用到新目标。

## 使用流程

1. 完成堆栈或后期操作，确保当前显示的是要复用的结果。
2. 点击工具栏“工作流”（⌥⌘W），输入名称，点击“读取当前步骤”。
3. 检查步骤、参数和迁移提示，然后“确认保存工作流”。尚未执行的调整不是新的处理步骤。导入的扁平成片没有原始操作历史，不能反推出工作流。
4. 选择一个已保存的工作流，再选择一个或多个新目标文件夹。
5. 选择输出位置，点击“检查目标”，核对照片数和校准帧要求后批量运行。

两种执行方式由已保存的步骤自动决定：

- 包含堆栈：每个目标文件夹作为一组曝光，输出一张成片，并依次执行保存的后期步骤。
- 仅有后期：文件夹里的每张照片单独处理，分别输出，不会把这些照片混在一起堆栈。

## 目标文件夹

每个文件夹对应一个目标。存在 `lights/` 时只读取该子目录，否则读取所选目录顶层的照片；不递归混合其他目标或旧的输出目录。原工作流用到了校准帧时，新目录必须提供相应的 `darks/`、`biases/`、`flats/` 子目录。不会悄悄省略缺失的校准步骤，也不会借用上一次的校准文件。

完整深空配方在新照片上重新分析和筛片，自动选择参考帧；原目标的逐帧保留/剔除决定及权重不迁移。算法和数值参数会保留，包括最大值等堆栈模式。适合深空的配方不一定适合星轨，复用前仍需检查堆栈模式、配准和去航迹设置。

## 保留与限制

- 支持完整深空配方、由原片重建的普通堆栈、Drizzle，以及裁切、背景、归一化、拉伸、曲线、降噪、对比、锐化、反卷积、色彩、缩星、彗差修正和自动去航迹/去云等后期步骤。
- 手工圈选的飞机线或云区不对应新图上的相同位置。保存时必须明确勾选自动重新检测，或取消保存；不会无提示地沿用旧选择。
- 目标保护椭圆、手工蒙版、自定义多图层混合、依赖外部中间配准序列或专用参考图的步骤，目前不能自动迁移，保存时会说明原因。普通不透明的同尺寸后期结果层可以按其处理链保存。
- 原片不修改，当前打开的项目不替换。每次运行都新建唯一输出目录，不覆盖已有结果。
- 一个任务失败会记录原因，其余任务继续；取消会保留已完成的结果和任务记录。重新运行会创建另一份输出。

## 保存位置与结果

工作流库为 `~/Library/Application Support/PhotonStack/workflows.json`，采用有大小限制的原子 JSON 写入。可以导入、导出单个工作流；导入会创建副本，不覆盖已有配方。库文件损坏时不会静默重置。

每次运行在指定位置创建 `PhotonStack-Workflow-<唯一编号>/`，包括：

- `workflow.json`：本次执行的固定配方，不含旧照片、旧缓存路径或素材 ID。
- `run.json`：任务状态、新输入及输出路径、失败原因。
- 每个任务的独立目录：名称包含序号、目标或照片名称和唯一标识，便于定位。`result.tiff` 为全分辨率输出，使用保存的导出设置；`processing/` 保留处理步骤和引擎报告供检查。

运行列表显示任务数、完成/失败数以及当前步骤；完成后可直接“显示成片”在访达中定位。总进度按任务和步骤累计，不会因第一张照片处理完成就提前显示整个批次完成。目标文件夹检查在后台进行，运行过程中仍可取消。

运行中的任务不能清理。处理结果经检查确认后，可以按项目产物保留策略管理中间文件。工作流配方本身不依赖这些中间文件。

## 验证入口

Swift 工作流专项测试名称以 `reusableWorkflow` 开头。设置 `PHOTONSTACK_TEST_CLI` 指向已编译的命令行引擎后，测试会实际生成 FITS 输入，捕获堆栈和后期处理链，再处理不同的新文件夹，检查像素、分辨率、原片不变、失败隔离和取消状态。
