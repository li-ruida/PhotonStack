# PhotonStack 第四轮审计复核

基线是 `bug-audit` 工作区在本轮修改前的源码快照，已包含此前的修复。第四轮的 9 项在该快照中都有对应代码路径。第二轮的 H7、14 个编号项及 M3 的核实依据另见 [第二轮记录](bug-audit-second-pass-2026-11-28.md)。

第二轮的 H7 在关闭后驻留窗口仍带有编辑标记时成立，14 个编号项也各有实际缺口。M3 所称的极小 sigma 导致整图 NaN 是误报，卷积在无有效权重时回退到原像素。M10 涉及高级工具设置的保存范围，L4 涉及手动裁剪与自动比例的优先级，两项都属于产品行为约定。

## 9 项缺陷

| 编号 | 影响和修复 |
| --- | --- |
| B1 | CLI 去除目录结尾的分隔符时保留当前目录。测试覆盖 `.`、`./`、`./.`、`.//` 和普通目录。各子命令仍执行自己的新建或复用规则。 |
| B2 | 工作流库的导出入口先校验当前项目和受保护素材。回归测试通过该入口选择项目 JSON、其链接别名和合法的新 JSON，并核对项目原文。 |
| B3 | SPCC 单文件导出、预览和默认深空配方使用私有临时目录，完成后独占发布。已有文件、悬空链接及发布时出现的同名对象均获保留。 |
| B4 | 外部图像工具配置通过同一文件描述符验证普通文件、拒绝终端链接并限量读取。恰好 65,536 字节的合法 JSON 可以加载。 |
| B5 | 目录输出提交前校验目标类型。已存在的合法目录交换后还要核对被换出对象的身份。同名普通文件会保留。 |
| B6 | 星层分离、背景复查、通道、母片配准、线性匹配、窄带、广义拉伸和 PSF 等入口在解码前检查输出父目录与占用情况，发布时再次检查。 |
| B7 | TIFF 读取器按文件字节序解析两个内联 `SHORT`。小端和大端的灰度加 alpha 图分别覆盖，避免将位深字段误作文件偏移。 |
| B8 | 光谱配置库将用户切换列表与程序选中导入项区分处理。归档列表导入后只刷新一次，取消的操作不能回写选择或显示错误。 |
| B9 | 原生 QA 窗口延迟采样使用可取消的主线程任务。窗口脱离后取消采样，原报告列出的 5 条隔离警告已消除。 |

## 20 项性能建议

| 编号 | 实际处理和适用条件 |
| --- | --- |
| P1 深空分析、配准和堆栈 | 按图像尺寸、算法及内存预算安排并发。复用参考星表，畸变配准从一次密集检测取得粗匹配星点。已知尺寸的 FITS 最多预读一帧，定制读帧或会回收输入的回调继续顺序执行。星点描述子共用距离缓冲，仅保存最近邻。空间索引用于候选和相互匹配，初始无位移先验的投票仍比较星对。 |
| P2 去马赛克和 CFA Drizzle | Menon 跳过随后会被覆盖的整帧双线性填充，保留无支持像素、覆盖率和局部回退。Menon、Ratio 和 CFA Drizzle 按行分工，Ratio 合并绿色平滑阶段并减少两个整帧缓冲。中间平面保留双精度。 |
| P3 背景提取 | 等权分位数使用选择算法，不等权选择对同值的歧义边界回到原排序规则。椭圆角度只计算一次，同一网格内按内存上限汇集通道样本。RBF 先前已有行并行，本次为 Apple 平台增加双精度分块向量对数。 |
| P4 轨迹修补 | 检测与移除共享亮度统计。主修补按不重叠行分工，后续 43 个条件清理位置只暂存写到的像素块。跨邻域需要的掩码仍保留，具体执行哪些清理取决于画面和检测结果。 |
| P5 频域叠加 | 只读取裁剪区域。预算允许时按帧读取一次并更新三个通道累加器，内存不足时按通道分批。 |
| P6 来源校验 | 合并 Swift 同阶段的重复校验，用最多 4 个工作任务、每次 4 MiB 分块计算 SHA-256。规范应用配方走本地解析，兼容配方保留 CLI 解析。校准元数据从参与哈希的相同字节读取。传感器校准及不超过 16 个输入的母片构建在同一描述符上随分块解码计算核验摘要，包含 FITS 填充和扩展。更大输入组限制同时打开的文件数。校准续跑复用本次已校验且身份未变的旧成品，新成品和显式检查仍完整校验。 |
| P7 元数据与预检 | SPCC 读取 FITS 头、尺寸与 WCS，预检有界并行，批量校准按路径复用母片头。 |
| P8 工作区刷新 | 进度和控制台使用按属性观察，文件可用性在后台检查。显示用配方按项目和设置缓存，成品列表延迟创建条目。实际执行仍重新校验输入。 |
| P9 图层与蒙版 | 实际滑块在拖动时更新本地刻度和数值，提交后在后台合成全分辨率预览。成功后才更新项目及撤销记录。手动预览和导出复用 Core Image 上下文，轨迹标注缓存定向底图，蒙版编辑器异步加载最长边 2048 的代理，当前笔触和已提交笔画分开绘制。 |
| P10 项目依赖 | 批量移除素材复用依赖索引，按批次重分组并重映射参考帧和权重。自动保存缓存普通文件身份，链接及其父目录仍重新检查。 |
| P11 校准与传感器模式 | 同一工作流复用平场均值。CPU 校准、模式残差和分块统计按区间执行，传感器模式估计按内存预算同时解码 1 至 4 帧。 |
| P12 数值处理 | 反卷积阻尼减少逐像素幂运算并处理比例溢出。马赛克按面板、方向和裁剪边复用匹配参考条带，缓存有独立容量上限。金字塔、背景降噪和深空显影的独立循环并行处理。堆栈使用与背景提取相同的加权分位数规则。 |
| P13 Metal | 原版已有共享缓冲复用及页对齐零拷贝路径。本次在同一命令缓冲内核对有限值，CPU 读取单个标志。CPU 要消费结果时仍等待 GPU 完成，允许缺失样本的内核保留其原有规则。 |
| P14 SPCC 与图像后处理 | 重放复用已解析星表。对照预览在内存中编码并核验，正式目标只发布一次。背景与星层后处理按区间执行，只对精确可表示的 16 位输入使用 sRGB 查表。 |
| P15 Seestar 导入 | 每次完成复制就追加并同步一条记录，结束时生成完整 JSON。恢复逻辑兼容旧清单、未写完的最后一条和已复制尚未记账的文件，继续回读目的盘校验 SHA-256。 |
| P16 产物校验 | 内部图像优先验证 ImageIO 状态、数量和尺寸，必要时解码缩略图。外部程序产物保留像素验证。目录分批并发检查，发布前再检查取消。8 像素缩略图的实际解码量由格式和解码器决定。 |
| P17 照片调整 | 交互预览复用几何变换与中间纹理，源文件发生变化时失效。导出仍使用全分辨率图，剪切告警保留透明度。 |
| P18 自动保存 | 300 毫秒内的编辑合并后再准备项目快照，后台串行写入紧凑 JSON。显式保存和项目切换等待必要写入完成。 |
| P19 筛片 | 搜索词索引随报告建立，展示列表由报告、选择、排序和筛选条件驱动。搜索缩小范围时同步调整详情选中项。 |
| P20 PSF 预览 | 用两次选择运算取得预览拉伸分位数，保留原有百分位位置与拉伸阈值。 |

## 样本与验收

真实样本来自 M31 的 2160×3840、16 位 GRBG FITS。比较本轮之前和之后的 Release CLI，交替运行两个版本，按各自产物的完整 SHA-256 对照。频域叠加另用 6 张 1024×768 的 RGBA 浮点合成帧，裁剪区域为 128×96。

单帧转换输入为 `Light_M 31_60.0s_IRCUT_20260911-205435.fit`，SHA-256 为 `6116c05dfc372e72a378716a403523fa2cd9ad7b2006f18c70926a4dda07ee33`。转换使用科学数值模式，背景测试使用其 Menon 输出。堆栈均打开 FITS 去马赛克，最低匹配阈值设为 3，其余参数沿用 CLI 默认值。

原生 QA 窗口使用独立数据目录。实际导入 4 张 M31 副本后完成筛片。搜索 `2.fit` 时列表和详情都切换到该帧，清空后恢复 4 张。通过原生入口确认堆栈并打开 `developed.tiff`，报告记录入栈 4/4、峰值同时分析 4 帧。原始 FITS 运行前后摘要一致。

表中为本机交替运行的中位数。单帧与频域每版各跑 3 次，堆栈每版各跑 2 次。两组 20 帧测试都配准了参考帧之外的 19 张，回退次数为 0。耗时包含 CLI 启动和成片写出，仅适用于这些输入、算法、机器和文件缓存状态。60 MP 数百帧、机械盘及低内存设备的耗时和界面帧率未测。

常规回归覆盖全部 84 项 CTest（含 Metal），Swift 共 653 项，其中 636 项通过、17 项由环境条件跳过。Seestar 的 14 项脚本测试通过。求解器超时测试曾在并行负载下先于 Python 测试替身就绪而失败，现用轻量本地子进程和就绪标记，独立断言超时、取消及后代进程退出。图层的原生控件提交、撤销及失败保留原状态由 Swift 模型测试覆盖，归档配置库的导入选择路径做了代码复核。

另用原生窗口生成的真实配方和报告，单独启用了常规套件中跳过的两项。真实报告读取通过。同一版本的 App 全分辨率导出测试中，强制重建耗时 11.665 秒，使用经过 SHA-256 核验的成片耗时 0.242 秒。两份 TIFF 逐字节一致，原片摘要保持一致。监测到的重放目录峰值分别为 530,841,600 字节和 0。该对照衡量同一版本的两种导出路径。

传感器母片另做 16 个和 18 个输入的对照，分别覆盖边读取边计算 SHA-256 和限制打开文件数的路径。每组的母片、接受计数图和输入清单均与本轮前逐字节相同。
