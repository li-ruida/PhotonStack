# PhotonStack 第三方体验与重构记录

本轮以首次使用者的完整路径为验收对象：导入 → 分析 → 筛片 → 堆栈 →
100% 复查 → 导出。检查范围覆盖架构、天文数值处理、结果解释、任务可靠性与 macOS 界面。
工作区原有改动保留，基线补丁和未跟踪源码归档在
`artifacts/third-party-review-20261104/baseline/`；不覆盖生产应用，也不修改原片。

## 已落实的改进

| 观察到的问题 | 改动与结果 |
| --- | --- |
| 根视图 6,014 行，窗口生命周期、预览、检查器和工具混杂 | 提取 17 个按职责组织的工作区文件，根视图约 650 行；原有行为做逐行对照复核 |
| 工作区模型同时管理异步状态和 JSON 解析 | 提取 14 个纯解码/校验方法至 `WorkspaceReportDecoder`，保留原接口及任务世代控制 |
| 大量子进程日志可无限占用内存；锁内通知可能重入 | 独立有界流解析器，完整 stdout 上限 32 MiB、stderr 尾部 256 KiB；锁外发通知，超限明确失败，输出仍走原子发布 |
| Float32 累加可溢出或丢失正负大数间的微弱差值 | 平均、加权及对应流式路径共用 Float64 信号/覆盖累计；输出仍为 Float32 |
| 旧报告缺测量时可能显示“0 张需复查” | 缺失测量、警告和原因统一生成质量线索；汇总、筛选、搜索、逐帧详情一致 |
| 失败报告仅凭配方一致便可能进入下一步 | 工作流完成状态必须同时具备成功报告；失败后明确返回检查与重新分析 |
| 整组星点均拉长时，相对筛片仍全部保留 | 保留相对筛选规则，新增绝对偏心率复查警告；参数改称“星点偏心率复查阈值” |
| 新用户无法判断该堆栈还是直接后期 | 欢迎页提供两个清晰入口、流程说明、原片保留说明和打开项目入口 |
| 固定尺寸工作台与大量底层参数挤占复查空间 | 工作台支持伸缩；已分析后的堆栈设置可折叠；参数页显示常用/已修改项，提供全参数搜索、中文选项及分组说明 |
| 处理完成后容易直接进入后期，忽略质量复查 | 突出“打开成图复查”，源帧线索与显示指标保持可展开；明确指引全图及 1:1 检查 |
| `deep-sky --help` 被当作错误配方参数 | 深空和显影命令支持 `--help`、`-h`、`help`，保留机器可读 schema 输出 |
| 原生导出重放将 `/run` 与 `/run/` 误判为不同目录 | 改为规范化真实路径比较，继续拒绝目录外及符号链接产物；真实引擎和原生导出均已复测成功 |

## 实测证据

### 数值与真实 FITS

- 最终 CMake/CTest：49 项全部通过，含高动态范围求均值、所有输入顺序下
  `[1e8, 1, -1e8] → 1/3`、部分覆盖的加权样本、失效像素与阈值边界。
- 真实样本：M31 的 8 张连续、同晚、每张 60 秒、2160×3840、GRBG Bayer FITS。
  默认深空全链路完成约 26.3 秒，8/8 入栈；7 张配准各有 845–912 个匹配，无降级。
- 平均堆栈约 2.8 秒完成。这里的普通平均运行未开启配准，用于数值/解码链路验证，
  不作为与默认配准 Sigma 成图的画质排名。
- 科学母片、背景母片和平均堆栈全像素检查：NaN/Inf 均为 0，负科学信号保留。
  默认成图 2092×3774；显示近黑约 1.984%、近白 0。
- 1200 px 预览可见 M31 结构和色彩，也可见部分星点拉长。新版分析仍保留 8/8，
  其中 5 张新增偏心率复查警告；这是信息完整性提升，不是假定它们必须全部排除。
- 所有真实输入处理前后 SHA256、大小与修改时间一致。

可复查的本地证据位于 `artifacts/third-party-review-20261104/`：
`engine-final-tests.log`、`real-fits-candidates.json`、`real-m31/run-summary.json`、
`real-m31/numerical-summary.json`、`real-m31/warning-validation.json`、

### 原生界面与状态

隔离 QA 程序使用独立设置、预览目录和测试项目。通过原生窗口实际操作确认：

1. 欢迎页两种任务入口、导入文件夹和工作流下一步可见。

5. 实际堆栈完成后，可从突出显示的复查按钮打开成图并切换到 100%。

7. 从原生“导出成片”入口保存成功，界面显示明确导出路径；产物为
   `native-workflow-export.tiff`（238×251，16-bit sRGB，按有效覆盖裁边）及处理溯源 sidecar。

## 准确性和资源边界

Float64 累计增加内存：2160×3840 RGBA 相比旧 Float32 累计约多 127 MiB，
但与输入帧数无关。它改善数值稳定性，不等同于光度标定、绝对颜色标定或测光误差模型。
[ccdproc 官方 combine 接口](https://docs.astropy.org/projects/ccdproc/en/latest/api/ccdproc.combine.html)
也将中间数据类型默认设为 Float64；本项目的正确性结论来自独立的解析样例测试。

FITS 是承载科学数组及元数据的容器，不能用显示是否明亮来判断线性数据是否有效；
可参阅 [NASA FITS 格式说明](https://fits.gsfc.nasa.gov/fits_primer.html)。本次仍区分
线性母片、观看用显影图和源帧记录，不把近黑/近白比例当作原片过曝率或最终画质评分。

8 张 M31 小样本和 7 张合成图覆盖了本轮关键链路，不能代表全部 711 帧、大型马赛克、
所有相机 RAW、完整校准帧组合和长时间内存峰值验收。后续架构演进应继续拆分模型中的
图层/缓存/标记渲染职责，并用现有取消、撤销、延迟结果与项目切换测试保护状态契约。
